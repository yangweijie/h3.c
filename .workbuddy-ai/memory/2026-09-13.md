## 修复 context-kit 自身的两个缺陷（已改 skill 源码）

skill 安装于 `~/.workbuddy-ai/skills/context-kit`，frontmatter 无 `agent_created`，因此不能用 SkillManage 修改，直接编辑了源码。

1. **条目正文文件互相覆盖（严重）**：`FileStorage.#resolve` 对每个路径段调用 `paths.sanitizeKey`，该函数是 ASCII-only 且截断到 64 字符，会把纯中文标题清成空串。结果 45 条条目只落盘 39 个文件：6 条纯中文标题（构建、测试与运行命令／环境变量与运行时开关／错误处理与日志约定／多模态条件构建／显存分层规划／测试体系）全部塌缩到同一个 `entries/md`，2 条撞在 `entries/Architecture_Design.md`。读取时按文件名回查，导致**标题与正文错配**（搜索"显存分层规划"返回"测试体系"的正文）。
   - 修法：在 `src/knowledge/schema.mjs` 新增共享函数 `entryContentKey(id)`，用「短 slug（≤48 字符）+ id 的 FNV-1a 短哈希」构造 key，保证截断后哈希仍在、不同 id 永不碰撞；`builder.mjs` 与 `store.mjs` 改为共用它（原先两处各有一份重复的 `sanitize` / `sanitizeEntryId`，正是漂移的来源），并删除这两份死代码。
2. **概览树没有摘要**：`renderOverview` 的 `renderTreeLines` 读 `entry.content`，但 builder 写入时把 content 剥离只存 `entries/*.md`，因此模块树只有标题；而注入文本里的 OVERVIEW_INTRO 明确承诺"标题下是截断摘要"。
   - 修法：`schema.normalizeEntry` 增加 `summary` 字段；`builder.write` 用新增的 `summarize()` 从正文派生单行摘要（≤180 字符）存入 index.json；`store.renderTreeLines` 优先读 `entry.summary`，回退到 `entry.content`（兼容 MemoryStorage 场景）。

回归：skill 自带 16 项测试全部通过（`node --test test/context-kit.test.mjs`；注意 `node --test test/` 在当前 Node 22 下会把目录当模块解析而报 MODULE_NOT_FOUND，要显式给文件名）。
3. **顺带修 `package.json` 的 `scripts.test`**：由 `node --test test/` 改为 `node --test test/*.test.mjs`，让 `npm test` 能跑通。
